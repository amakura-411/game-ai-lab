# 在庫管理CLI 仕様書

## 要件

商品は、次の情報を持つ。

- 商品ID
- 商品名
- 価格
- 在庫数

最低4件の商品を初期データとして用意すること。

CLIから次の操作を行えること。

1. 商品一覧を表示する
2. 商品IDから商品を検索する
3. 商品を入荷する
4. 商品を販売する
5. 全商品の在庫金額を表示する
6. プログラムを終了する

---

## 商品一覧

登録されている商品について、最低限次の情報を表示すること。

- 商品ID
- 商品名
- 価格
- 在庫数

表示形式は自分で決めてよい。

商品一覧の表示では、商品情報を変更しない。

---

## 商品検索

商品IDを入力すると、該当する商品を検索する。

商品が存在する場合は、その商品のアドレスを `Product*` として返す。

商品が存在しない場合は `nullptr` を返す。

呼び出し側は `nullptr` かどうかを確認し、存在しない場合はエラーメッセージを表示する。

```cpp
Product* product = searchById(products, id);

if (product == nullptr) {
    // 商品が存在しない場合の処理
}
```

---

## 入荷

商品IDと入荷数を指定する。

正常な場合、指定した商品の在庫数を増やすこと。

商品IDが存在しない場合は、新規商品として登録すること（商品名・価格・入荷数を入力させる）。

次の場合は在庫を変更しないこと。

- 入荷数が0以下

商品の在庫数を実際に変更するため、対象の商品は参照渡しで扱う。

---

## 販売

商品IDと販売数を指定する。

正常な場合、指定した商品の在庫数を減らすこと。

次の場合は在庫を変更しないこと。

- 商品IDが存在しない
- 販売数が0以下
- 販売数が現在の在庫数を超えている

商品の在庫数を実際に変更するため、対象の商品は参照渡しで扱う。

---

## 在庫金額

各商品の、

`価格 × 在庫数`

を計算し、その合計金額を表示すること。

価格は整数として扱う。

---

## 制約

- UIは不要
- CLIで動作すればよい
- 商品は `struct` で表現する
- 複数の商品は `std::vector<Product>` で管理する
- 商品IDは `std::string` で管理する
- 価格は `int` で管理する
- `main()` にすべての処理を書かない
- 商品一覧表示、検索、入荷、販売、在庫金額表示などは必要に応じて関数へ分ける
- 商品検索では `Product*` と `nullptr` を使用する
- classは必須にしない
- 継承は使わない
- 動的メモリ確保を自分で行う必要はない
- `new` / `delete` は使用しなくてよい
- テンプレートを自作する必要はない
- 最初から高度な最適化をしない

---

## 決定済み仕様

### 商品IDの型

`std::string` を使用する。

例：

```cpp
std::string id;
```

数字だけでなく、`"001"` のようなIDも扱えるものとする。

---

### 価格の型

`int` を使用する。

小数の価格は今回扱わない。

```cpp
int price;
```

---

### 商品の型

商品は `struct` で定義する。

最低限、次の情報を持つ。

```cpp
struct Product {
    std::string id;
    std::string name;
    int price;
    int quantity;
};
```

---

### 商品一覧の管理

複数の商品は `std::vector<Product>` で管理する。

```cpp
std::vector<Product> products;
```

`std::vector` は、複数の `Product` を保持する可変長の入れ物として使用する。

---

### CLIメニューの表示形式

1. プログラムを実行する
2. 以下のメニューを表示する

```text
アクション

1. 商品一覧を表示する
2. 商品IDから商品を検索する
3. 商品を入荷する
4. 商品を販売する
5. 全商品の在庫金額を表示する
6. プログラムを終了する
```

ユーザーは番号を入力し、画面の案内に従って操作する。

各処理が完了したら、再度メニューを表示する。

---

### 商品検索に失敗した場合

`nullptr` を返す。

エラーメッセージは、検索結果を受け取った側で表示する。

例：

```text
指定された商品IDの商品は存在しません。
```

---

## 関数名および戻り値

### 1. 商品一覧を表示する

関数名：

```cpp
showAll
```

戻り値：

```cpp
void
```

商品一覧の表示までこの関数が担当するため、戻り値は不要。

商品情報を変更しないため、商品一覧は `const` 参照で受け取る。

イメージ：

```cpp
void showAll(const std::vector<Product>& products);
```

---

### 2. 商品IDから商品を検索する

関数名：

```cpp
searchById
```

戻り値：

```cpp
Product*
```

見つかった場合は対象商品のアドレスを返す。

見つからなかった場合は `nullptr` を返す。

---

### 3. 商品を入荷する

関数名：

```cpp
arrival
```

戻り値：

```cpp
void
```

商品IDの検索から在庫数の変更まで、この関数が担当する。

指定した商品IDが存在しない場合は、新規商品として `products` に追加する（`std::vector::push_back()` を使用）。

商品一覧を変更するため、`products` は参照渡しで受け取る。

イメージ：

```cpp
void arrival(std::vector<Product>& products);
```

---

### 4. 商品を販売する

関数名：

```cpp
sell
```

戻り値：

```cpp
void
```

商品IDの検索から在庫数の変更まで、この関数が担当する。

商品一覧を変更するため、`products` は参照渡しで受け取る。

イメージ：

```cpp
void sell(std::vector<Product>& products);
```

---

### 5. 全商品の在庫金額を表示する

関数名：

```cpp
displayAmount
```

戻り値：

```cpp
void
```

在庫金額の計算から画面表示まで、この関数が担当する。

商品情報は変更しないため、商品一覧は `const` 参照で受け取る。

イメージ：

```cpp
void displayAmount(const std::vector<Product>& products);
```

---

### 6. プログラムを終了する

関数名：

```cpp
quit
```

戻り値：

```cpp
void
```

ただし、終了処理が単純な場合は専用関数を作らず、メインループを終了するだけでもよい。

## 引数の渡し方

今回、次の3種類を用途によって使い分ける。

### 値渡し

```cpp
Product product
```

値をコピーして関数へ渡す。

関数内で変更しても、元の `Product` は変更されない。

小さい値や、意図的にコピーを作りたい場合に使用する。

---

### 参照渡し

```cpp
Product& product
```

元の `Product` を直接扱う。

関数内で変更すると、呼び出し元の `Product` にも変更が反映される。

今回では主に次の処理で使用する。

- 入荷
- 販売

---

### const参照

```cpp
const Product& product
```

コピーせずに元の `Product` を参照する。

ただし、その参照を使って値を変更することは禁止される。

今回では、商品情報を読むだけの処理で使用する。

例：

- 商品表示
- 商品情報を使った計算

複数の商品を読むだけの場合は、

```cpp
const std::vector<Product>& products
```

のように `vector` 自体を `const` 参照で受け取る。

---

## ポインタと商品検索

今回の商品検索では、ポインタの基本も使用する。

```cpp
Product* product;
```

`Product*` は `Product` が存在するメモリアドレスを保持する型。

商品が見つかった場合、その商品のアドレスを返す。

商品が見つからない場合は、

```cpp
nullptr
```

を返す。

ポインタから商品の値を扱う方法については、実装時に確認すること。

今回は以下について深掘りする必要はない。

- `new`
- `delete`
- 動的メモリ確保
- スマートポインタ
- ポインタの寿命に関する高度な問題

---

## 今回特に考えること

関数の引数として、次の3つがどう違うかを意識する。

```cpp
Product product;
Product& product;
const Product& product;
```

実装中に次の観点で考えること。

- 元データを変更したいか
- 元データを変更してはいけないか
- コピーを作る必要があるか
- 大きなデータを毎回コピーする必要があるか
- 読むだけなのに変更可能な参照を渡していないか

さらに、次についても確認する。

```cpp
Product*
nullptr
```

- ポインタには何が入っているのか
- 商品が見つからない状態をなぜ `nullptr` で表せるのか
- ポインタから実際の商品を扱うにはどうするのか

## 完成条件

次を満たせば、この課題は完成扱いとする。

- プログラムがコンパイルできる
- `struct Product` を定義している
- `std::vector<Product>` で複数商品を管理している
- 最低4件の商品データが存在する
- 商品一覧を表示できる
- 商品検索ができる
- 存在しない商品を検索した場合にエラー表示できる
- 入荷できる
- 販売できる
- 不正な販売・入荷を拒否できる
- 在庫金額を計算・表示できる
- プログラムを終了できる
- `main()` 以外にも関数を分けている
- `Product*` と `nullptr` を使った商品検索ができる
- 自分の引数設計について説明できる

さらに、実装後に次の違いを自分の言葉で説明できること。

```text
Product product
Product& product
const Product& product
Product*
nullptr
```

また、次の質問に答えられること。

1. なぜ入荷・販売では `Product&` を使ったのか
2. なぜ一覧表示では `const &` を使ったのか
3. なぜ全部を値渡しにしなかったのか
4. なぜ全部を `&` にしなかったのか
5. 商品検索に失敗したことを `nullptr` でどう表現しているのか
6. `std::vector<Product>` は何を表しているのか

完璧な設計や高度なC++の書き方は求めない。

## 余裕があれば

必須要件が終わった場合のみ、次から1つ選ぶ。

### 1. 在庫切れ表示

在庫数が0の商品について、一覧画面で在庫切れと分かるようにする。

### 2. 商品追加（実装済み）

CLIから新しい商品を追加できるようにする。

`arrival`（入荷）機能に統合済み。未登録の商品IDを入荷しようとした場合、新規商品として登録する。

### 3. 操作履歴

入荷・販売した内容を簡単な履歴として保持し、最後に表示する。

---

## レビュー時に確認すること

実装後は、次の観点でレビューする。

- 要件を満たしているか
- `main()` に処理が集中していないか
- 変更する必要がない引数を変更可能な参照で渡していないか
- 不要なコピーが発生していないか
- `const` を付ける理由を説明できるか
- `Product*` を返す理由を説明できるか
- `nullptr` の確認を忘れていないか
- エラー時に在庫データが壊れないか
- 関数名から処理内容を推測できるか
- 関数名と実際の責務・戻り値が一致しているか
