# NPC装備システム：所有権とRAII 仕様書

## 1. 概要

C++でNPCが装備品を所有するCLIプログラムを作成する。

NPCは装備品を1つだけ所有でき、
装備品の所有権を別のNPCへ移動できるものとする。

今回の課題では、`std::unique_ptr` を利用して
「誰がオブジェクトを所有しているのか」をコード上で表現し、
`std::move` とRAIIの基礎を学ぶ。

---

## 2. 目的

以下のC++基礎を学習する。

- `std::unique_ptr`
- `std::make_unique`
- `std::move`
- 所有権
- 所有権の移動
- `nullptr` 状態
- デストラクタ
- スコープとオブジェクト寿命
- RAII
- `delete` を直接使用しないメモリ管理

---

## 3. Equipmentが持つ情報

装備品は最低限、以下の情報を持つ。

| 項目       | 内容                    |
| ---------- | ----------------------- |
| 装備名     | 装備品の表示名          |
| 攻撃力補正 | NPCの攻撃力に加算する値 |

例：

```text
Iron Sword
Attack Bonus: 5
```

---

## 4. NPCが持つ情報

NPCは最低限、以下の情報を持つ。

| 項目       | 内容                     |
| ---------- | ------------------------ |
| 名前       | NPCの表示名              |
| 基礎攻撃力 | 装備補正を含まない攻撃力 |
| 装備       | 現在所有している装備品   |

NPCが所有できる装備品は最大1つとする。

NPCは「装備あり」または「装備なし」のどちらかの状態を持つ。

---

## 5. 必須機能

### 5.1 装備品の生成

装備品を動的に生成できること。

装備品の生成には、所有者が明確になる方法を使用すること。

生成時に最低限、以下を指定する。

- 装備名
- 攻撃力補正

### 5.2 NPCへの装備

NPCが装備品の所有権を受け取れること。

装備後はNPCがその装備品の所有者となる。

表示例：

```text
[Slime]
Base Attack: 3
Equipment: Iron Sword
Attack Bonus: 5
Total Attack: 8
```

### 5.3 装備なし状態

NPCが装備を所有していない状態を表現できること。

表示例：

```text
[Slime]
Base Attack: 3
Equipment: None
Total Attack: 3
```

### 5.4 装備品の所有権移動

あるNPCが所有する装備品を、別のNPCへ移動できること。

例：

```text
移動前

Slime
Equipment: Iron Sword

Dragon
Equipment: None
```

SlimeからDragonへ装備を渡した後：

```text
移動後

Slime
Equipment: None

Dragon
Equipment: Iron Sword
```

装備品そのものをコピーして増やしてはいけない。

### 5.5 移動前後の状態確認

所有権を移動する前後で、移動元と移動先が装備を所有しているか確認できること。

最低限、以下を確認する。

```text
移動前
移動元   : 装備あり
移動先   : 装備なし

移動後
移動元   : 装備なし
移動先   : 装備あり
```

### 5.6 デストラクタの確認

`Equipment` が破棄されたことを確認できるようにする。

破棄時には、以下のようなログを表示する。

```text
Iron Sword destroyed
```

表示文言は変更してよい。

## 6. 実験ケース

### 6.1 通常の所有

```text
Equipment生成
↓
NPCが所有
↓
NPCを使用
↓
スコープ終了
↓
Equipment破棄
```

自分で `delete` を呼ばなくてもEquipmentが破棄されることを確認する。

### 6.2 所有権の移動

```text
Equipment生成
↓
Slimeが所有
↓
Dragonへ所有権を移動
↓
Slimeは装備なし
↓
Dragonが所有
↓
スコープ終了
↓
Equipment破棄
```

1つのEquipmentに対して、同時に複数の所有者が存在しないこと。

### 6.3 一時スコープ

```text
{
    NPC生成
    Equipment生成
    NPCがEquipmentを所有
}

ここでスコープ終了
```

スコープを抜けたタイミングで、関連するデストラクタが呼び出されることを確認する。

## 7. CLI機能

最低限、以下の操作または確認ができること。

```text
1. NPC一覧・装備状態を表示
2. 装備品を生成する
3. NPC A に装備させる
4. NPC A から NPC B へ装備を渡す
5. NPC B から NPC A へ装備を渡す
6. 所有状態を確認する
0. プログラムを終了する
```

メニュー番号・NPC名・文言は変更してよい。

CLIではなく、処理を順番に実行して実験結果を表示する形式でもよい。

## 8. 異常系

| ケース                        | 期待する挙動                             |
| ----------------------------- | ---------------------------------------- |
| 装備を持っていないNPCから移動 | 何も移動しない                           |
| 移動後の元NPC                 | 装備なしとして扱う                       |
| 装備なし状態で情報表示        | 不正アクセスしない                       |
| NPCが既に装備を持っている     | 上書き・拒否のどちらかを仕様として決める |
| 空の所有状態                  | 安全に判定できる                         |
| スコープ終了                  | 所有中のEquipmentが自動破棄される        |

## 9. 制約

### 9.1 `std::unique_ptr` を使用する

Equipmentの単独所有を表現するために、`std::unique_ptr` を使用すること。

### 9.2 `std::make_unique` を使用する

Equipmentの生成では、`std::make_unique` を使用すること。

### 9.3 所有権移動に `std::move` を使用する

装備品の所有権を移動するときは、コピーではなく所有権の移動を行うこと。

### 9.4 `new` / `delete` を直接使用しない

今回の課題では、生の `new` と `delete` を直接使用しないこと。

### 9.5 所有者を曖昧にしない

1つのEquipmentに対して「今誰が所有しているのか」を常に説明できる設計にすること。

## 11. 完了条件

以下をすべて満たしたら課題完了とする。

- `Equipment` を作成できる
- `std::unique_ptr` を使用している
- `std::make_unique` でEquipmentを生成している
- NPCがEquipmentを1つ所有できる
- 装備なし状態を安全に扱える
- NPC間で装備の所有権を移動できる
- 所有権移動に `std::move` を使用している
- 移動後、移動元が装備を所有していないことを確認できる
- 移動後、移動先が装備を所有していることを確認できる
- Equipmentのデストラクタ呼び出しを確認できる
- スコープ終了時にEquipmentが自動破棄される
- `new` / `delete` を直接使用していない
